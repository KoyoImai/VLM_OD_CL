**書誌情報**: Xu Wang, Zihan Lin, Yixin Zhang, Zilei Wang（University of Science and Technology of China / Institute of Artificial Intelligence, Hefei Comprehensive National Science Center）。CVPR 2025（CVF Open Access 版、論文ページ 6249–6260）。コード公開: https://github.com/Never-wx/dgs 。本要約のページ参照は論文のページ番号（6249〜）による。

## 1. 問題設定: CDIOD（Cross-Domain Incremental Object Detection）

タスク系列 {D_1, ..., D_t} を逐次学習する。各フェーズ t のタスク D_t = {(x_n, y_n)} はドメイン P_t からのサンプルで、ラベルはラベル空間 C_t に属する。フェーズ t では C_t のクラスのみアノテーションされ、ラベル空間はフェーズ間で互いに素（C_t ∩ C_t' = ∅, t ≠ t'）である。フェーズ t 完了後は既出クラス全体 C_1:t = C_1:(t-1) ∪ C_t を検出できることが要求され、評価はタスク非依存（task-agnostic、タスク ID を与えない）で行う（p.6251 §3.1）。従来の IOD が全フェーズ同一ドメイン（P_t = P_t'）を仮定するのに対し、CDIOD はドメイン内増分（P_t = P_t'）とドメイン間増分（P_t ≠ P_t'）の両方を含む。同一画像内に未アノテーションの既出クラスが再出現し得る（missing annotations と background shift が生じる、p.6251 §2.2）。

ベース検出器は全手法とも **Grounding-DINO-T**（Objects365 + GoldG + Cap4M で事前学習、p.6254 Implementation Details）。

著者らは CDIOD の課題を3軸で定量化する（p.6251 §3.3）: (i) ドメイン内安定性 = ドメイン内の平均忘却 (1/(N−1)) Σ_{i=1}^{N−1} (W_i^i − W_i^N)（W_i^i はタスク i 直後の性能、W_i^N は N フェーズ後の性能）、(ii) ドメイン間安定性 = あるデータセットの性能を全フェーズにわたり追跡、(iii) 適応性 = 各タスク直後の即時性能。分析の結論は、フル FT は大きな分布シフトで忘却が激しく、PEFT 系（タスク別アダプタ＋タスク ID 推定ルーティング）は安定だがルーティング誤りと適応性不足で CDIOD では劣る、というもの（p.6252 §3.4、Fig. 2, Fig. 5）。

## 2. 提案手法 DGS（Dynamic Group Subspace）

タスクを分布類似度で動的にグループ化し、グループ内で知識共有・グループ間で知識分離する枠組み。3つの構成要素からなる（p.6253 §4.1）。

### 2.1 DTG（Dynamic Task Grouping）— タスクのグループ割当（p.6252–6253 §4.2）

各タスクを特徴空間のガウス分布としてモデル化する。新タスク D_t に対し、**凍結した画像バックボーン**で特徴 F_t を抽出し、μ_t = E[F_t]、Σ_t = Var(F_t) を推定して N_t = N(μ_t, Σ_t) とする。グループ g（所属タスク集合 {k ∈ g}）との類似度は最小 KL divergence

KL(t, g) = min_{k∈g} D_KL(N_t ‖ N_k)　…(式2)

で測り、g* = argmin_g KL(t, g) として、割当は

φ(t) = g*（KL(t, g*) < τ のとき）、そうでなければ新グループを作成　…(式3)

とする。拡張閾値は **τ = 150** に固定（全実験共通、p.6256）。τ の感度は表5（後述）のとおり 100〜600 で安定。

### 2.2 IGA（Incremental Group Adapters）— アダプタの配置（p.6253 §4.3）

各グループ g_i に IGA モジュール A_i を持たせ、グループ内のタスク k ごとにタスク別アダプタ α^k_{g_i} を管理する。アダプタは **LoRA**（rank r = 16）で、挿入位置は **feature enhancer 各層の画像側・テキスト側両方の FFN**。FFN 入力 h に対する出力は

FFN(h) + Σ_{k∈g_i} m_k · B_k A_k h　…(式4)

（A_k, B_k はタスク k の LoRA 行列、m_k は有効アダプタを示す one-hot マスク）。挿入位置とランクの検討（p.6256 Fig. 6）では、rank 16 で enhancer の画像・テキスト両 FFN に入れる構成が性能とパラメータ効率の最良バランスとされる（decoder のみは大きく劣り約 41–42 AP、fusion 層や片側 FFN も FFN 両側に劣る。decoder を追加してもパラメータ増に見合う向上なし）。

### 2.3 IGC（Intra-Group Consolidation）— グループ内統合（p.6253–6254 §4.4）

線形なパラメータ増加を防ぐため、各グループは共有の base アダプタ α_g^base を保持し、毎タスク終了後に反復的にマージする:

α_g^base ← λ α_g^base + (1 − λ) α_g^new,　λ ∈ [0, 1]　…(式5)

更新は LoRA の A・B 両行列に適用し、マージ後 α_g^new は破棄する。マージ係数は「0.2 for both A and B matrices」（p.6254。式5 の λ と 1−λ のどちらが 0.2 かは本文に明記なし。「欠落情報」参照）。

**Group Initialization**: 新タスクが既存グループに割当てられた場合、その新アダプタ α_g^new は乱数初期化ではなく**グループの base アダプタ α_g^base から初期化**する。独立に学習したモデルの重み平均は高損失障壁を跨ぎ得るが、fine-tuning 前後のモデルは同一 basin に留まるため、この初期化がマージの安定性を保証する（p.6253）。

**Group Alignment**: α_g^new を**タスク固有のクラス空間ではなくグループ全体のクラス空間**で学習する。欠落アノテーションは α_g^base が生成する**擬似ラベル**で補い、さらに KD 損失

L_kd = L(M(x; α_g^new), M(x; α_g^base))　…(式6)

で α_g^new をグループ共有表現に整合させる。L は「topology-based distillation loss」とだけ記され、具体形は本文にない（p.6254）。

### 2.4 学習パイプラインと損失（p.6254 §4.5）

二値指示子 δ(t)（タスク t が既存グループ所属なら 1、新グループなら 0）を用い、学習目的は

L = L_align + L_reg + δ(t) · L_kd　…(式7)

L_align は focal loss（領域–テキスト整合の分類）、L_reg は L1 + GIoU。**新グループのタスクは制約なしで学習**（適応性重視）、**既存グループのタスクは IGC（擬似ラベル＋KD＋base 初期化）で学習**（安定性重視）という動的パイプラインである。忘却抑制の機構は「グループ内統合（base への漸進マージ・base 初期化・Group Alignment KD）とグループ間分離（別グループのアダプタは触らない）」に、適応の機構は「新規分布に対する新グループ作成と無制約学習」にある。

学習条件（p.6254 Implementation Details): RTX 3090 × 8、総バッチ 16。**LoRA パラメータのみ更新**（rank 16）。学習率は初期 1e-3 で 11 エポック、最後に 0.1 倍に減衰。**δ(t) = 1 のとき初期学習率を 5e-4 に半減**。τ = 150、マージ係数 0.2。

### 2.5 推論（Group Routing、p.6254）

テスト画像 x ごとにバックボーンで特徴統計を抽出してガウス近似 N_x を作り、保存済みグループ分布との最小 KL でグループ g* を同定し、対応する A_{g*} を全該当層で有効化して予測する。**タスク ID は不要**（画像単位の自動ルーティング）。単一画像からの統計推定の詳細は Appendix Sec. B とされ本 PDF に無い。タスク単位ルーティング（AE・NMC・分布ベース）はドメイン内混同で精度が低いのに対し、グループ単位ルーティングは全タスクで安定して高精度（p.6256 Fig. 5）。

## 4. アブレーション（0-5・10 フェーズ設定、表4、p.6256）

EPP は追加パラメータ率。(1) ベースモデル（zero-shot）Avg 24.7 → (2) 単一 LoRA を逐次更新 0.40% で 29.5（適応するが激しく忘却）→ (3) タスク別 LoRA（T-LoRA、ルーティング付き）4.00% で 51.5（線形なパラメータ増とルーティング誤り）→ (4) T-LoRA を全部ナイーブに重み平均 4.00% で 43.8（異ドメイン間の知識差で大幅劣化）→ (5) DTG によるグループ化＋式5 マージ（G-LoRA）1.20% で 54.3 → (6) + Group Initialization で 56.7 → (7) + Group Alignment（完全形）で **60.2**。すなわち「グループ化マージ +10.5（対ナイーブマージ）、base 初期化 +2.4、Group Alignment +3.5」が内訳。

**τ の感度（表5）**: τ=1 で 10 グループ（タスク別に退化）Avg 51.5、τ=50 で 6 グループ 58.9、τ=100 で 4 グループ 59.6、**τ=150 で 3 グループ 60.2**、τ=400 で 3 グループ 60.0、τ=600 で 3 グループ 60.2、τ=1000 で 2 グループ 48.7（異質なタスクの併合で干渉）。

**パラメータ成長（Fig. 7）**: ZiRa・MR-GDINO・T-LoRA は追加パラメータがフェーズ数に線形で約 4〜10M まで成長するのに対し、DGS は新グループ作成時のみ増える段差状で約 1〜2M に留まり、性能も全フェーズで最高帯を維持。

## 6. 本プロジェクトとの関係（事実のみ）

ベース検出器は Grounding-DINO-T（Objects365 + GoldG + Cap4M）であり、本プロジェクトの MM-Grounding DINO Swin-T（O365 + GoldG + GRIT + V3Det、COCO 非含有）とはアーキテクチャ系統は同じだが実装と事前学習データが異なる。問題設定は CDIOD＝**クラス増分とドメイン増分の複合**（ラベル空間をフェーズ間で互いに素に分割し、同一データセットを複数フェーズに割る）であり、本プロジェクトの RF100 系列＝**ドメイン増分**（各ドメインの全クラスを1タスクで学習、クラス分割なし）とは設定が一致しない。一方、表2 の IVLOD ベンチマーク（ODinW-13 full-shot 逐次学習 + ZCOCO、ZiRa の設定）は、本プロジェクトの ODinW-13 系列（exp_033/042 等、note12）と同一プロトコルであり、この表の数値（DGS: ZCOCO 46.4 / Avg 60.9、ZiRa: 46.1 / 59.7）は同じ土俵の報告値である（ただしベース検出器と事前学習データが上記のとおり異なる）。比較手法として ZiRa・MR-GDINO・GCD・CL-DETR・MD-DETR を含み、DitHub は related work での引用のみで実験比較には含まれない。手法の位置づけとしては、LoRA を feature enhancer の FFN（画像・テキスト両側）に挿入する点で本プロジェクトの蒸留E が対象とする feature enhancer と同じモジュールに介入し、タスク境界でのアダプタ統合（式5）は DitHub の式4 マージ（λ_B=0.7）と操作の型が近く、「新規分布なら無制約・既知分布なら制約付き」という損失の切替え（式7 の δ(t)）は ZiRa 系の設計とは異なる動的制御である。忘却抑制がバッファ（リプレイ）を一切使わない点も本プロジェクトのバッファ不使用系列（EWC・InfLoRA・LoRA）と条件が揃う。

### 7.1 KD 損失の具体形（Appendix B.4、式 7–11）

クラス c のプロトタイプ p_c = (1/N_c) Σ α_i q_i（最終デコーダ層のクエリ特徴 q_i を
予測ロジット由来の信頼度 α_i で重み付き平均）。既出クラス C_{1:t−1} 上の対距離行列
R_ij = ||p_i − p_j||₂ を作り、蒸留損失は **||R^new − R^base||₂**（R^base は base アダプタに
切り替えて得る）。テキスト側も同様に作り、
**L_kd = γ₁·L_topology_image + γ₂·L_topology_text、γ₁=3・γ₂=5（B.5: 全実験共通）**。
= 公式実装の `inter_loss.py`（`inter_query_relation`・`inter_text_relation_partial`）の
'inter-class' 分岐と一致し、γ は公開 config の img_loss/text_loss の重み 3.0/5.0 と一致する。
**注意: 公開 config は `feat_distn.type='inter-intra'` だが、実装に存在する分岐は
'inter-class' のみで、公開設定のままでは KD が実行されない。Appendix B.5 が全実験で
KD 有効（δ(t)=1 のとき）と明記していることから、これはリリース時の名称ズレとみられる。**
logits 蒸留（実装の loss_ld）は最終式 (13) に存在せず、config が省略しているのは正しい。

### 7.2 DTG・ルーティングの詳細（B.2・B.3・C.2）

- 特徴は凍結バックボーンの last-stage（多レベルはオプション、既定は last）。
  μ_t・Σ_t（不偏共分散＋εI）で N(μ_t, Σ_t)。比較は対称 KL（式 3）。
- 推論は GAP した 1 ベクトル z を N(z, Σ_t)（**共分散はタスクのものを共有**。
  1 枚からの分散推定を避けるため）としてタスク分布と対称 KL、最小を選ぶ。
- **OOD 閾値はオプション**（超過で IGA 無効＝zero-shot）。th_ood の感度（CDIOD、
  Table 5）: 200 → ZCOCO 0.470 / タスク Avg 57.3、500（既定）→ 0.458 / 60.2。
- **DTG はタスクあたり最低 260 枚で安定**（Fig. 5）。それ未満ではガウス推定が
  ノイズで Min KL が跳ね上がり、過剰に新グループを作る（著者が明示的に認める限界。
  ODinW-13 の Mushroom 41 枚・Packages 95 枚はこの領域）。
- ルーティング精度は入力解像度に頑健（800×1333 で 0.998、Table 9）。

### 7.3 その他

- λ_merge（式 5 の base 側重み）= 0.2。感度（Table 4）: 0.0→57.5、0.2→60.2（最良）、
  0.7→23.6。マージ無しは新タスクへ過適合、大きすぎると更新を過剰拘束。
- 擬似ラベル: 固定閾値 σ の単純方式。σ=0.4 採用（Table 8: P/R トレードオフ）。
  **ドメイン遷移（新グループ）では擬似ラベルも KD も明示的に無効**（stage1）。
  「pseudo-labeling は既知ドメインでのみ安全に使える」という設計判断。
- 学習目的（式 12–13）: L = λ_focal·L_focal + λ_L1·L_L1 + λ_GIoU·L_GIoU + δ(t)·L_kd、
  λ = 1/5/2、γ₁=3・γ₂=5。
- Table 2: DGS の学習パラメータ 2.06M（1.2%）= 3 グループ × 688,128 と厳密一致
  （enhancer 両側 FFN・r=16 の LoRA 数の裏取り）。
