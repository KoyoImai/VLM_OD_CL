# EWC 実装ノート（projects/ewc_cl）

exp_042 用。原論文（Kirkpatrick et al., PNAS 2017）と公開実装（公式実装は存在しない）
との対応・差分の正本。監査 2026-08-15。実装検証の結果は `projects/ewc_cl/README.md`。

## 論文との対応

| 論文 | 本実装 | 検証 |
|---|---|---|
| 式(3): `L = L_B + Σ_i (λ/2)·F_i·(θ_i−θ*_i)²` | `loss_ewc = (λ/2)·[Σ A_iθ_i² − 2B_iθ_i + const]`（A=ΣF_k、B=ΣF_k·θ*_k） | 勾配が解析値 λ(Aθ−B) と一致（相対 1.8e-7）。タスク別保持と値・勾配一致 |
| 多タスク: タスク別二次項 or 一本に畳む（§2 本文が等価性を明記） | 2 バッファの厳密等価変形（タスク数によらず O(1) メモリ） | 3 タスクの素朴実装と一致 |
| Fisher: 対角・一次微分のみから計算（本文 142-144 行） | 学習と同じ検出損失の勾配²の per-sample 平均（経験 Fisher） | 非負・有限、θ=θ* でペナルティ 0.0 |
| Atari: タスクごとに 100 ミニバッチで Fisher 再計算・λ=400 | 上限枚数 config（既定 1,000、seed 固定抽出）。λ はパイロットで決定 | — |

- 検出損失（Hungarian マッチング含む複合損失）は厳密な負の対数尤度でないため、
  勾配²は厳密な Fisher 情報ではなく重要度のヒューリスティック。分類で経験 Fisher を
  使う場合と同型の近似で、下記の実装慣行の範囲内。

## 検出器特有の実装判断

1. **dropout 無効化**: `model.eval()` は GroundingDINO の loss 経路（学習時専用の
   encoder 出力）を壊すため、eval にした上で検出器本体の training フラグだけを
   立て直す。`F.dropout(training=self.training)` を使う層（DecomposedMHA・融合層）も
   これで確実に切れ、loss はビット単位で決定的（Dropout モジュール列挙では
   3〜5% の揺れが残ることを実測）。
2. **状態はファイルで持ち回り**、checkpoint に含めない（肥大・unexpected keys 回避）。
3. **学習対象 = EWC 対象**を構成要素単位で config 選択（'all' で全モジュール）。
   誤記は空選択にならずエラー。状態ロード時に形状検証。
4. **数値注記**: θ≈θ* では勾配 λF(θ−θ*) が「大きな 2 数の差」になり、fp32 の丸めが
   相対 1e-3〜1e-2 に見えることがある（絶対誤差 ~1e-7·|Fθ*| で無害）。
