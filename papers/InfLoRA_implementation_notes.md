exp_042 用。論文（Liang & Li, CVPR 2024）と公式実装（liangyanshuo/InfLoRA、113★）
との対応・差分の正本。監査 2026-08-15。実装検証の結果は `projects/lora_cl/README.md`。

## 論文・公式実装との対応

| 論文 / 公式 | 本実装 | 検証 |
|---|---|---|
| 記法: B（r×d_I、設計・凍結）/ A（d_O×r、0 初期化・学習） | lora_A / lora_B（lora_cl の既存記法。役割は同一） | A 凍結・B のみ更新を実測 |
| forward `e = Wh + Σ A_iB_ih`（係数なし） | alpha=r → scaling=1 | 層単位で (W+BA)x = 分岐 forward |
| タスク後 `W_t = W_{t-1} + A_tB_t` | merge_lora.py（scaling=1） | マージ済み plain がその場マージとビット一致、検出も分岐と一致（0.011 px） |
| 勾配空間 ≈ 入力空間（GPM 系の命題） | 挿入層の入力共分散 Σxᵀx/n を running mean で蓄積（公式 cur_matrix と同式） | 収集が forward を変えない（loss ビット一致） |
| 設計: Ĥ=(I−MMᵀ)H → SVD 上位 r（公式は U[:,:r].T/√3） | `dual_gpm.design_A`（公式の片側射影 (I−MMᵀ)·C の形を採用） | 公式スタブと射影子一致（<1e-5） |
| DualGPM: M または M⊥ を保持（論文 §3.2.2）、閾値 lamb→lame 線形 | `dual_gpm.update_dual_gpm`（公式コードの移植） | **公式コードの逐語スタブと 4 タスクで基底・型が完全一致（<1e-6）** |
| 学習前後の 2 回の全データパス | prepare / update_memory の 2 CLI（上限枚数・seed 固定） | 実ランナー 30 iter を含む一連の流れを実測 |

## 公式実装との意図的な差分（根拠つき）

1. **retain 型の初期化**（`dual_gpm.py`）: 公式は最初のタスクで r≥d/2 のとき 'retain' と
   ラベルしつつ主部分空間 U[:,:r] を保存するが、論文の定義（M⊥ の保持）と直後の
   整合 assert に矛盾する未実行の潜在バグ。直交補 U[:,r:] を保存する。
2. **設計行列のランク不足への対処**（`dual_gpm.py` `design_A`）: 1 クラスタスクでは
   プロンプトが全画像で同一のため、テキスト側（BERT）層の共分散の実効ランクが
   r を下回る（実測: pistols で ≈3。fp32 のノイズ特異値は相対 ~1e-5 に出るため
   閾値は相対 1e-3）。実効ランクを超える A の行は SVD の任意の直交補完でメモリと
   直交しない（実測: 該当行がメモリ方向に整列）ため 0 にする（その成分の ΔW=0）。
   ViT 分類の公式実装は入力の多様性からこの領域に入らない。
3. **dropout**: 収集は model.eval()＋検出器 training フラグのみ有効（決定的）。
   公式は ViT の素の forward（この論点自体が生じない）。
4. **optimizer**: 公式 SGD/Adam＋cosine → exp_042 共通枠の AdamW＋MultiStep
   （design.md §6 に逸脱として記録）。
5. **挿入箇所**: 公式は ViT の k・v 射影のみ → 本実装は config 選択
   （exp_042 は exp_038 条件A と同じ 232 層。ユーザー決定 2026-08-15）。
6. 分類固有の要素（タスク別分類器・local CE・評価時のタスク ID 推定クラスタリング）は
   持ち込まない（ドメイン増分・プロンプト付きの本設定では不要）。

## 細部の注記

- 射影は公式コードどおり片側 `(I−MMᵀ)·C`。論文の ĤĤᵀ=(I−MMᵀ)C(I−MMᵀ) とは
  特異値の重みが僅かに違うが、左特異ベクトルが M⊥ に入る性質は同じ。
- running mean はトークン数で重み付けされる。ViT は 1 画像のトークン数が固定だが、
  本検出器は画像・プロンプトごとに可変で、トークン数の多い画像がやや重くなる
  （公式と同じ更新式に従った帰結）。
- 干渉抑制の実測（タスク間・実データ）: pistols のメモリ（task1 エネルギー 61.9% 被覆）
  で PascalVOC の設計を射影すると、task1 入力への応答エネルギーが射影なし設計の
  中央値 23.3% に減る。対照は「射影なしの top-r 設計」（乱数 A はほぼ零分散方向に
  エネルギーを撒くため対照として不適。実測で確認）。
