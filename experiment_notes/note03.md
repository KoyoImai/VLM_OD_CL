# 実験3

## 位置付け
「問い2：新しいドメインの適応において学習が必要なモジュールはどこか」の2サイクル目．
実験2で「特徴抽出・融合部」が新ドメインの適応の役割を担っていることが判明した．
しかし，「特徴抽出・融合部」には，Image Backbone（Swin Transformer）や Text Backbone（BERT），neck や text_feat_map，feature enhancer など複数のモジュールが含まれる．
これらのモジュールを全て使用した「特徴抽出・融合部」が適応を担うことは実験2で示せたが，各モジュールや機能のいずれかのみが適応を担うのか，全てのモジュールと機能が適応に必要かは不明である．
そこで，「特徴抽出・融合部」に含まれる機能の細分化によって，適応を担う機能を探索する．


## 目的
実験2の条件A「特徴抽出・融合部」のモジュールを細分化する場合，以下のように分割できる．

- Image Backbone（Swin Transformer）：入力画像から特徴を抽出
- neck：Image Backboneの出力特徴の次元数をテキスト側と揃える
- Text Backbone（BERT）：入力テキストから特徴を抽出
- text_feat_map：Text Backboneの出力特徴の次元数を画像側と揃える
- feature enhancer：画像特徴とテキスト特徴の融合

実験2では，これらのモジュールを全てまとめて学習・評価しており，「画像特徴抽出が適応を担うのか？」「画像-テキスト特徴抽出が適応を担うのか？」「画像-テキスト特徴の融合が適応を担うのか？」，あるいは「特徴抽出・融合全体で適応を担うのか？」という問いについては結論が出ていない.

そこで本実験では，「特徴抽出・融合」に含まれるモジュールを上記に示すレベルで細分化し，各モジュールを機能ごとにまとめて学習・凍結することで，真に新ドメインへの適応に必要な機能がどこかを探索する．
各モジュールは，機能ごとに以下のようにまとめる．

- 画像特徴抽出：Image Backbone + neck
- テキスト特徴抽出：Text Backbone + text_feat_map
- 画像-言語特徴融合：feature enhancer


## 実験種別
探索実験


## 問い
Image Backbone，neck，Text Backbone，text_feat_map，feature enhancerのうち，どのモジュールまたはモジュールの組み合わせを学習することで，実験2の条件Aや条件3と同等の新ドメイン適応性能を得られるか．


## 条件
- 条件A1（画像特徴抽出）：Image Backbone + neck のみ学習
- 条件A2（テキスト特徴抽出）：Text Backbone + text_feat_map のみ学習（実験1の条件2で学習済みのため，既存結果を参照）
- 条件A3（特徴融合）：feature enhancer のみ学習
- 条件A4（画像-テキスト特徴抽出）：Image Backbone + neck + Text Backbone + text_feat_map のみ学習
- 条件A5（画像特徴抽出-特徴融合）：Image Backbone + neck + feature enhancer のみ学習
- 条件A6（テキスト特徴抽出-特徴融合）：Text Backbone + text_feat_map + feature enhancer のみ学習
- データセット：Roboflow100を用いて単一ドメインでのみ学習．ドメインは underwater，videogames，electromagneticの3種類．
- 評価：適応ドメインの mAP と COCO2017 のゼロショット mAP．判定は適応ドメインのみで，観察用にCOCO2017のゼロショット性能も測る．
- 学習率：学習可能モジュールの学習率は実験1における条件3（フルファインチューニング）と同一とする


## 分岐規則
条件3（フルファインチューニング）時のドメイン適応性能（mAP）の90% 以上の精度を達成した場合，その組み合わせ（機能群）を次の仮説検証へと持ち越す．
複数の組み合わせで条件を達成した場合，それら全てを次の実験へと持ち越し，どの組み合わせでも条件達成がなければ，実験2の条件Aのみ次の実験へと持ち越す．
