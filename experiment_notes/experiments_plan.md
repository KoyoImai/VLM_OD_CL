# 実験計画

## 実験1：比較ベースラインの用意

### 目的 
比較手法を網羅的に学習・評価することで比較ベースラインの整備と問題点の確認

### 前提
- 条件A：全モジュール学習可能
- 条件B：特徴抽出部 + 特徴融合部を学習可能
- バッファサイズ：汎用ドメインは 1,000，各ドメインは 500 のバッファサイズを割り当てる．選択は全てランダムに実行．
- バッチの内訳（リプレイフリー）：現在ドメイン4
- バッチの内訳（リプレイ）：現在ドメイン4，汎用ドメイン1，過去ドメイン1でミニバッチを作成する．過去ドメインのデータはランダムに選択する．1ドメイン目については，現在ドメイン4，汎用ドメイン2．
- 使用ドメイン：underwater → electromagnetic → videogames の 3 ドメインでのみ学習．6ドメインは最終段階で実行する．
- ポック数や学習率などのハイパラは，全てのドメインで共通の値を使用する．


### 比較手法
- ファインチューニング（条件A・B）：リプレイなどを行わない単純なファインチューニング．全モジュール or 一部モジュール学習可能
- 素朴リプレイチューニング（条件A・B）：リプレイを導入したファインチューニング．全モジュール or 一部モジュール学習可能
- ZiRa：従来手法 ZiRa
- ZiRa + リプレイ：従来手法 ZiRa にリプレイを追加（リプレイ手法との公平な比較のため）
- DitHub：従来手法 DitHub（余裕があれば）
- DitHub + リプレイ：従来手法 DitHub にリプレイを追加（リプレイ手法との公平な比較のため，余裕があれば）
- 個別チューニング（条件A，条件B）：個別のドメインのみでモデルをファインチューニング
- ゼロショット：事前学習済みパラメータを凍結し，各ドメインでゼロショット推論
- オラクル（条件A）：全てのドメインを同時に学習（Object365は含めない）
- ZiRa（個別）；ZiRaを各ドメインで個別に学習


### 評価プロトコル
- 新ドメイン適応力：学習直後のドメインに対する mAP
- 過去ドメイン保持力：過去に学習したドメインに対する mAP（ドメインごとに個別に計算）
- 汎用知識保持力：COCO のゼロショット mAP


### 注記
- Object365については，事前学習データセットに含まれているため，汎用バッファのデータとして適切と考えられる．クラスも365の全てを使用する．
- AとBの決定基準については，結果を見てから柔軟に対応する．もし明確に差が出ない場合は，条件AとBの両方を実験2以降で使用する．
- 汎用知識の保持能力は COCO でのみ評価．必要になった際は，学習したパラメータで後日評価を実行する．
- 学習時のテキスト入力は，画像に含まれる物体カテゴリ（正例）とランダムに選ばれた同一ドメイン内のカテゴリ（負例）から構成され，長さは256に固定する．（変更はしない）
- 各ドメインで学習後のパラメータは保存し，後日再利用可能．



## 実験2：提案手法のベース用意

### 目的 
提案手法のベースとなる骨組みを実装，学習・評価し，改善点を洗い出す．

### 前提
- 条件A：全モジュール学習可能
- 条件B：画像言語特徴抽出部 + 特徴融合部を学習可能
- 蒸留A：バッファ内データを対象に画像 Backbone の出力特徴（画像特徴）で蒸留
- 蒸留B：バッファ内データを対象にテキスト Backbone の出力特徴（テキスト特徴）で蒸留
- 蒸留C：バッファ内データを対象に画像特徴とテキスト特徴で蒸留
- 蒸留D：バッファ内データを対象に画像-テキスト特徴融合後の出力特徴で蒸留
- 蒸留E：画像特徴，テキスト特徴，融合後特徴全てで蒸留
- 蒸留重み：実装，実行時の損失の値を見てから決定
- 蒸留形式：L2ノルム

### 提案手法のベース
- 蒸留A ~ E全てを実行．ただし，学習可能モジュールは，実験1の結果を確認してから条件Aと条件Bのどちらを使用するかを決定する．
- 蒸留のみ構成は不要
