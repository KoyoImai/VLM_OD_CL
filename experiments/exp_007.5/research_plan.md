## 1. 研究テーマと課題
事前学習済み VLM（MM-Grounding DINO）を対象とした **ドメイン増加型 物体検出 継続学習**。
- 課題1: 事前学習に乏しいドメインでの検出性能低下。
- 課題2: 新ドメイン学習による破滅的忘却（汎用知識＋過去ドメイン知識の消失）。

## 2. 貢献（3点）と進捗
- **C1 ベンチマーク構築** … **完了**（RF100 6ドメイン + COCO=ZCOCO、解像度(800,1333)・seed=0・eval base config・CL評価枠組み）。
- **C2 忘却の機序分析** … **完了**（exp_007）。手法駆動のため supporting だが、機序を因果的に解明。
- **C3 機序に基づく忘却抑制手法（LoRA, タスクごとにマージ）** … これから。**主貢献**。
- 主貢献の重心は **C3（手法）= 手法駆動**。ZiRa/DitHub/O-LoRA 等を上回ることで貢献を立てる。incremental 可。

## 3. 手法方針（確定）
- **本体凍結 ＋ LoRA。各タスク学習後に LoRA をベース重みへマージ**（InfLoRA/再パラメータ化方式、**パラメータ数一定**）。
  - LoRA は分離・保持しない（モジュール式/DitHub 型は不採用）。
- **中心課題（exp_007 由来）**: マージ＝共有重み更新なので「適応と忘却が同一部分空間を奪い合う」問題が直撃。
  hard 直交化は適応を壊す（exp_007 E）。→ 核心は「**マージしても奪い合いを最小化する更新の作り方**」
  （過去ドメインのみ直交化＋COCO は ZiL 的 soft 保護、rank/スケール抑制、トレードオフ点の探索）。

## 4. これまでの実験（内容と結果）

### exp_000: underwater zero-shot 評価
- 事前学習モデルを fine-tune なしで underwater valid 評価 → **mAP=0.051**。継続学習の出発点を初取得。

### exp_001: COCO + RF100 各ドメイン zero-shot（lower bound 表）
| 対象 | mAP |
|---|---:|
| COCO2017 | **0.504** |
| underwater | 0.051 |
| aerial | 0.034 |
| electromagnetic | 0.024 |
| videogames | 0.016 |
| documents | 0.006 |
| microscopic | 0.002 |
- 含意: 汎用(COCO)と専門ドメインで **10〜250倍差**（課題1の定量化）。

### exp_002 / exp_002.5: 評価プロトコル確定
- 解像度感度分析(28評価): **640/800/1024 は誤差範囲、短辺1333で精度崩壊**（COCO 0.504→0.021）、正方形固定は非正方形のみ悪化。
- 決定: **入力解像度 (800,1333) keep_ratio に統一**、seed=0/deterministic=False、COCO用/RF100用 eval base config 整備。

### exp_003: underwater 全体FT（backbone・言語 0.1×）
- underwater 0.051→**0.340**（適応）、COCO 0.504→**0.438（−13.1%）**（忘却）。

### exp_004: underwater 凍結FT（backbone・言語 凍結）
- underwater **0.316**、COCO **0.414（−17.9%）**。
- **凍結は適応↓・忘却↑（両負け）** → 忘却源は backbone でなく**共有検出経路**。

### exp_005: 全6ドメイン 単独 凍結FT（忘却の普遍性）
| ドメイン | 適応(zs→FT) | COCO忘却(0.504→) | 忘却率 |
|---|---|---:|---:|
| underwater | 0.051→0.316 | 0.414 | −17.9% |
| electromagnetic | 0.024→0.454 | 0.331 | −34.3% |
| microscopic | 0.002→0.499 | 0.327 | −35.1% |
| videogames | 0.016→0.719 | 0.324 | −35.7% |
| aerial | 0.034→0.468 | 0.318 | −36.9% |
| documents | 0.006→0.478 | 0.275 | −45.4% |
- **全ドメインで COCO 低下＝忘却は普遍**。距離依存（underwater 近い→小、documents 遠い→大）。

### exp_006: 2ドメイン逐次 aerial→D2（過去ドメイン忘却）
基準: aerial 単独FT後 **aerial=0.468 / COCO=0.318**。
| D2 (aerial→) | aerial(D1) | D1忘却 | D2適応 | COCO |
|---|---:|---:|---:|---:|
| videogames | 0.241 | −48.5% | 0.698 | 0.214 |
| electromagnetic | 0.147 | −68.6% | 0.466 | 0.216 |
| microscopic | 0.127 | −72.9% | 0.503 | 0.163 |
| underwater | 0.113 | −75.9% | 0.313 | 0.355↑ |
| documents | 0.099 | −78.8% | 0.481 | 0.128 |
- **過去ドメイン D1 も全ケースで忘却**（−48〜−79%）。新ドメイン D2 の適応は単独FTとほぼ同等（**非対称・FWT≈0**）。
- underwater(COCO近) を学ぶと COCO は回復（0.318→0.355）。

### exp_007: 忘却の機序分析（C2）
- **B 低ランク性**: 適応は中程度の低ランク（上位16特異値で 56〜89%）→ LoRA rank は中程度（≥16目安）。
- **C/D 部分空間干渉と忘却の相関**: **相関なし**（活性化部分空間の重なりは忘却の良い予測子でない）。
- **E 直交除去の因果検証**（ΔW から COCO 部分空間成分を除去）:
  | ドメイン | COCO(元→除去) | 自ドメイン(元→除去) | 適応保持率 |
  |---|---|---|---|
  | documents | 0.275→**0.480**✓ | 0.478→**0.089**✗ | 18% |
  | underwater | 0.414→**0.486**✓ | 0.316→**0.168**✗ | 44% |
- **結論（機序）**: 忘却=共有重みの COCO 部分空間成分（除けば回復＝因果確認）。**だが適応も同部分空間に依存**
  （除くと崩壊）＝**適応と忘却が同一部分空間を奪い合う**（両極で普遍、遠いほど依存大）。
  → **hard 直交化では COCO 保持と適応を両立できない**。

## 6. 今後の計画
**スコープ方針**: 当面は **最大 3〜4 ドメインの逐次学習**で開発・検証。**6ドメイン全逐次は最後**（最終確認のみ）。
**開発ドメイン（確定）**: **underwater（COCO近）→ electromagnetic（中）→ documents（COCO遠）** の3ドメイン（近→遠）。
**前段（exp_008）**: 手法実装の前に、まず**単純な LoRA を追加した学習・評価**で LoRA 組込みを確立し挙動を把握する。

**優先順位（確定）**:
1. **提案手法（マージ方式 LoRA）の実装・実験** ＋ 比較に必要なベースライン（同じ3〜4ドメインで取得）
2. **ドメイン順序の影響**
3. **6ドメイン逐次学習で最終確認**（最後）

### 優先1: 提案手法の実装・実験（3〜4ドメイン）
- **手法**: 本体凍結＋**タスクごとに LoRA をマージ**（パラメータ数一定）。
  中心課題＝奪い合いの最小化（過去ドメインのみ直交化＋COCO は soft 保護(ZiL類似)／rank・スケール抑制／トレードオフ点探索）。
  挿入箇所＝共有検出経路（encoder/decoder/neck/head の Linear）、backbone・言語は凍結。rank 中程度（exp_007 B）。
- **同時に取る比較基盤（同一3〜4ドメイン・同一順序）**:
  - 下限 = **素朴逐次FT**、上限 = **joint 多タスク学習**（§6.1）。補助上限 = per-domain 単独FT（exp_005）。
  - 比較手法 = ZiRa / O-LoRA / InfLoRA（/ DitHub）。
- 指標: R[i,j] / Avg / Forgetting / ZCOCO / hAP。

### 優先2: ドメイン順序の影響
- 同じ少数ドメインで複数順序を試し、Avg/Forgetting/ZCOCO の頑健性（順序依存）を確認。

### 優先3: 6ドメイン逐次（最終確認）
- 開発した手法を 6ドメイン全逐次で総合評価（最後にのみ実施）。

### 6.1 joint 多タスク学習（上限）の進め方
- 対象ドメインの train を **ConcatDataset で結合し1モデルを同時学習**（同時に全部見る＝忘却なし＝適応上限）。
- **各画像は自ドメインのクラス名のみをプロンプト**（`return_classes=True`）。全クラスを1プロンプトに連結しないため
  **テキスト長制限は発生しない**（videogames の max_text_len=512 等の単独ドメイン対応は従来通り）。
- 設定は単独/逐次FTと統一（凍結・lr1e-4・実効64・seed0）。規模不均衡は RepeatDataset 等で均衡化。
  `bbox_head.num_classes` は対象ドメインの最大クラス数。評価は各ドメイン＋COCO を個別に。
- 実装注意: 異クラス集合の dataset を ConcatDataset 結合する際の metainfo 整合（MM-GDINO 多データセット学習に前例）。

### Phase 後段: アブレーション・分析 → 執筆。

## 7. 主要な確定事実（要点）
- 忘却は**普遍・深刻・非対称**（過去のみ）、**忘却源=共有検出経路**、**距離依存**。
- 忘却の正体=**共有重みの COCO/過去ドメイン部分空間成分**（因果確認）。だが**適応も同部分空間に依存**＝奪い合い。
- → 手法は **base凍結＋タスクごとマージ LoRA**で、**奪い合いを最小化する更新**を作るのが核心。
