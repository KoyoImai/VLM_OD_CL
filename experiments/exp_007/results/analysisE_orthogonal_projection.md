# exp_007 分析E：直交除去の因果検証（documents）

## 設定
documents 単独FT の重み更新 ΔW から、**COCO の活性化部分空間成分を直交除去**したモデル
`W' = W_base + ΔW(I − S_COCO S_COCOᵀ)` を作り、COCO 回復とドメイン保持を評価。
S_COCO は各層の COCO 活性化共分散の上位固有ベクトル（累積エネルギー energy）。

## 結果
| 設定 | 除去した更新エネルギー | COCO mAP | documents mAP |
|---|---:|---:|---:|
| base（zero-shot） | — | 0.504 | 0.006 |
| documents FT（元） | 0 | 0.275 | 0.478 |
| 直交除去 E=0.90 | 36.6% | **0.480** | **0.089** |
| 直交除去 E=0.99 | 70.5% | **0.487** | **0.025** |

## 結論（因果的に確認された機序）
1. **忘却の原因は「更新が COCO 部分空間に乗った成分」**。それを除くと COCO はほぼ zero-shot まで回復（0.275→0.48）。
   → 分析C/D の相関は出なかったが、**因果介入(E)で機序自体は実証**。
2. **ドメイン適応に必要な方向が COCO 部分空間の中にある**。更新を1/3除いただけで documents 適応の8割が消失。
   → **適応と忘却が同じ部分空間を奪い合う（トレードオフが直結）**。

## 手法への含意（重要）
- **共有重みを COCO 部分空間と直交化する素朴な InfLoRA 型は本設定では不成立**
  （COCO を守る＝ドメイン適応を失う）。検出では COCO とドメインが共有検出特徴空間を強く共有するため。
- **正しい方向**: base を凍結（COCO 忘却ゼロ）したまま、**ドメイン専用 LoRA 分岐を分離して加える**
  （モジュール式 / 条件付き適用、DitHub 的）。または ZiRa の ZiL のような soft トレードオフ。
- → 「直交化」から「**base 凍結＋ドメイン分離 LoRA**」へ手法設計を更新すべき、という機序駆動の知見。

## 追試：underwater（COCO に近いドメイン）でも同じ
| 設定 | 除去エネルギー | COCO mAP | underwater mAP |
|---|---:|---:|---:|
| base | — | 0.504 | 0.051 |
| underwater FT | 0 | 0.414 | 0.316 |
| 直交除去 E=0.90 | 40.5% | **0.486** | **0.168** |
| 直交除去 E=0.99 | 72.8% | **0.494** | **0.096** |

→ 近いドメインでも「COCO 回復・自ドメイン劣化」は同じ。**奪い合いは普遍的**。
ただし保持率は underwater 44% > documents 18%（E=0.90）で、**COCO から遠いドメインほど適応が COCO 方向に依存**し崩壊が激しい。

## 留意
- 検証は documents（COCO忘却最大）。普遍性確認のため近傍ドメイン（underwater）等でも追試する価値あり。
- 層ごと直交射影＋複数層同時適用での end-to-end 評価。COCO 回復が 0.48〜0.49 で zero-shot 0.504 に僅か届かないのは
  norm/bias 等 非対象パラメータが ft のままのため（更新の2D weight 成分のみ除去）。
