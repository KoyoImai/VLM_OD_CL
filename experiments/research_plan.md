# 研究計画 草案（Research Plan / Draft）

作成日: 2026-06-20。exp_000〜006.5 の知見を踏まえた研究全体の計画案。**議論用の草案であり随時更新する。**

---

## 0. 研究テーマ（再掲）
事前学習済み Vision-Language Model（MM-Grounding DINO）を対象とした、
**ドメインが増加する物体検出の継続学習**。未研究の設定であり、以下2課題に取り組む。
- 課題1: 事前学習に乏しいドメインでの検出性能低下。
- 課題2: 新ドメイン学習による破滅的忘却（汎用知識＋過去ドメイン知識の消失）。

---

## 1. 中心的な主張（Thesis / ストーリー）
事前学習 VLM 検出器は強力なオープン語彙検出を持つが、
1. **専門ドメインで大きく性能低下**する（zero-shot で COCO 0.504 vs 専門 0.002〜0.051）。
2. 新ドメインへ逐次 fine-tune すると、**汎用知識(COCO)も過去ドメインも破滅的に忘却**する
   （COCO −18〜−45%、過去ドメイン −48〜−79%）。
3. 忘却は **(a) 共有のテキスト対照検出デコーダで起き、(b) 過去方向にのみ非対称に、(c) ドメイン間距離に依存して** 生じる。

→ 本研究は **(i) この設定のベンチマーク化**、**(ii) 忘却の機序分析**、
**(iii) 機序に基づく忘却抑制手法** を提供する。

---

## 2. 想定する貢献（Contributions）
- **C1: ベンチマーク**。RF100 を 6ドメイン（+COCO を汎用保持の基準=ZCOCO）に統合した
  「増加ドメイン型 VLM 物体検出 継続学習」評価枠組み（指標・順序・プロトコルを含む）。
- **C2: 分析**。忘却が共有検出デコーダで生じ、非対称・距離依存であることの実証的解明
  （凍結 ablation・単独/逐次の比較・距離との相関）。
- **C3: 手法（LoRA ベース）**。**本体を凍結し LoRA（低ランク適応）で各ドメインに適応する**ことで、
  共有検出デコーダの破壊を避けつつ新ドメインを学習する忘却抑制手法。
  下限(素朴FT)・上限(joint)に対する有効性検証。
  - 動機: exp_004 で「本体凍結＋検出デコーダ全FT」は忘却が大きかった。LoRA なら**ベース重みを保持**し
    低ランクの差分のみ学習するため、共有検出経路の破壊を最小化でき、COCO/過去ドメインの保持が期待できる。

## 4. 今後の計画

### Phase 1: ベンチマークとベースライン確立
- **exp_007 — 6ドメイン逐次 素朴FT（下限）**。凍結設定・seed固定・1順序。
  各段で全既習ドメイン＋COCO を評価し精度行列 R[i,j] を構築。CL指標を算出。
- **exp_008 — joint 多タスク学習（上限）**。全ドメイン同時学習。忘却なしの到達点。
  （補助の上限として exp_005 の per-domain 単独FT も oracle に利用）
- **exp_009 — ドメイン順序の影響**。複数順序（例3）で Avg/Forgetting/ZCOCO の頑健性を確認。
- 目的: 「下限〜上限のギャップ＝改善余地」を数値で確定し、手法評価の土台を作る。

### Phase 2: 忘却抑制手法の開発（LoRA ベース）
**大枠の方針: 本体凍結 ＋ LoRA による継続適応。** ベース重みを壊さず低ランク差分のみ学習する。

#### LoRA の設計空間（要検討・本研究の新規性の核）
1. **挿入箇所**: どのモジュールに LoRA を入れるか。
   - 分析より **共有検出デコーダ/エンコーダ/neck/head の Linear** が第一候補（忘却源を直接保護）。
   - backbone（Swin）・language（BERT）への付与は任意（exp_004 で凍結維持が無難と判明）。
2. **ドメイン系列での LoRA 管理**（最重要・忘却に直結）:
   - (a) **単一 LoRA 継続更新**: 実装簡単だが LoRA 自体が後続ドメインで上書き＝忘却が残る。
   - (b) **ドメイン別 LoRA（パラメータ分離）**: 過去ドメイン忘却ゼロだが、推論時にドメイン識別が必要。
   - (c) **統合型（ZiRa 流の再パラメータ化）**: 学習後に LoRA をベースへ統合し新 LoRA を学習、
     ノルム正則化で過去/ゼロショットを保護。メモリ線形増加を防ぐ。
3. **推論時のドメイン識別（task-ID）**: 本評価は各ドメインのクラス名（テキスト）で評価するため、
   プロンプト経由で実質ドメインが与えられる。COCO(ZCOCO) はベース経路で評価する必要 → 
   LoRA が COCO を壊さない仕組み（ゲーティング/低スケール/ZiL 的ノルム制約）が要る。
4. **ゼロショット(COCO)保持**: LoRA 出力ノルムの抑制（ZiL 類似）や、ベース経路との残差スケール調整。
5. **ハイパラ**: rank r、スケーリング α、対象層、ドメインごとの r 配分。

#### 既存手法との関係・差別化
- **ZiRa** は再パラメータ化可能な並列分岐＋ZiL で本研究と発想が近い。LoRA はその分岐を低ランク化した形と見なせる。
  → 「LoRA＋ゼロショット保持＋（必要なら）統合」で ZiRa を VLM 検出の継続学習に発展させる位置づけ。
- CL 用 LoRA の一般系（ドメイン別 LoRA プール / 直交化・正則化 LoRA / LoRA 統合）も比較・参考にする。
- 比較対象（CL 代表系）: 素朴FT(下限)・joint(上限)・正則化(EWC/LwF)・リプレイ(exemplar)・全FT凍結(exp_005/006)。

#### 実装メモ
- MM-Grounding DINO（mmdet）の Linear 層へ LoRA を注入する必要（decoder/encoder の attention・FFN 等）。
  既存 PEFT 流の実装 or 手動ラッパを mmdet のモデル構築に組み込む。Phase 2 冒頭で実装タスクを置く。

### Phase 3: 手法評価・アブレーション
- exp_007/008 と同一プロトコルで手法を評価（下限・上限の間でどこまで回復するか）。
- アブレーション: アダプタ有無、ZiL 有無、正則化強度、順序頑健性。
- 分析: 手法が共有検出デコーダの歪みを実際に抑えているか（重み差分・出力ノルム）。

### Phase 4: 分析の深化と執筆
- 忘却量とドメイン距離（CLIP特徴/語彙重なり）の定量的相関。
- 失敗例の可視化（忘却前後の予測比較）。
- 論文化（ベンチマーク＋分析＋手法）。

## 5. 評価プロトコル（確定/暫定）
- **解像度**: (800,1333) keep_ratio（確定, exp_002.5）。**seed**: 0 固定（確定）。
- **指標（ZiRa準拠 + CL標準）**:
  - 精度行列 R[i,j]（タスク i 学習後のタスク j 精度）。
  - **Avg**: 全ドメイン最終平均 mAP。
  - **Forgetting (F)**: 各ドメインの (最大過去精度 − 最終精度) の平均。
  - **ZCOCO**: COCO 保持 mAP（汎用知識）。
  - **hAP**: ZCOCO と Avg の調和平均。
  - 補助: BWT/FWT。
- **対象**: RF100 6ドメイン（real_world 除外）＋ COCO（ZCOCO 基準）。

## 6. 主要な決定事項（要議論）
1. **手法の方向性**: ZiRa型を踏襲して再現＋改良するか、独自手法（共有デコーダ保護等）を主軸にするか。
   → 貢献 C3 の新規性に直結。
2. **順序の扱い**: 1順序で進めて後から順序 ablation か、最初から複数順序平均か（コスト）。
3. **上限の定義**: joint 学習を主上限にするか、per-domain oracle で代替するか。
4. **スコープ/規模**: 6ドメインで確定か、将来 real_world(405クラス) や 7ドメインまで拡張するか。
5. **計算予算**: 6ドメイン逐次×順序数×手法数 は大きい。優先順位付けが必要。

---

## 7. リスクと対策
- **計算コスト**: 逐次×順序×手法で膨張。→ まず1順序で下限/上限を固め、手法は有望なものに絞る。
- **手法の新規性**: ZiRa の単純再現では貢献が弱い。→ 分析(共有デコーダ・距離依存)を手法設計に組み込み差別化。
- **多クラス安定性**: videogames(512トークン) 等のメモリ。→ per-GPU8+累積2 で確立済み。
- **評価の公平性**: seed/解像度/プロトコル統一は確立済み。手法比較も同一条件で。
