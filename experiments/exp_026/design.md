## 0. 位置付け・目的・仮説

- **位置付け**: 実験1の残りのうち、**逐次学習ではない参照点**をまとめて取る実験。exp_024/025 が「逐次でリプレイ無し」を担うのに対し、本実験は逐次学習の**上限と下限の基準線**を用意する。
- **目的**: note04 の比較表を読むために必要な参照点を揃える。具体的には
  - **個別チューニング**＝逐次に伴う忘却が一切無い場合の適応（各ドメインの到達可能な適応性能）、
  - **オラクル**＝全ドメインを同時に見た場合の上限、
  - **ゼロショット**＝学習しない場合の下限、
  を測る。これらが無いと、逐次学習の結果（exp_023/024/025）が「良い／悪い」を判断する基準が無い。
- **仮説**: 本実験は基準線の整備が主目的であり、強い仮説検証ではない。個別チューニング ≥ 逐次学習（適応）、オラクル ≥ 逐次学習（全ドメイン平均）となることが期待されるが、**判定は実測値で行う**。

## 1. 構成（4つのサブ実験）

| # | 内容 | 学習 | 本数 |
|---|---|---|---|
| **026-1** | 個別チューニング（**条件A**＝全モジュール） | 各ドメインを θ0 から独立に学習 | 3（3ドメイン） |
| **026-2** | 個別チューニング（**条件B**＝特徴抽出+融合） | 同上・学習範囲のみ条件B | 3 |
| **026-3** | **個別 ZiRa** | ZiRa を各ドメインで独立に学習 | 3 |
| **026-4** | **オラクル（条件A）** | 3ドメインを**同時**に学習（Objects365 は含めない） | 1 |
| **026-5** | **ゼロショット（再確認）** | 学習なし。θ0 を凍結して評価のみ | 評価 7 本 |

- 条件A/B の呼称は note04 の定義（A＝全モジュール、B＝特徴抽出+融合）に従う。
- 026-1〜4 は**リプレイ無し**（バッファを混ぜない）。026-4 のオラクルも note04 の指定どおり Objects365 を含めない。

## 2. 対象ドメイン

- **026-1〜4**: underwater / electromagnetic / videogames（note04 の使用ドメイン3つ）。
- **026-5（ゼロショット）**: **RF100 6ドメイン全て**（underwater / aerial / videogames / microscopic / documents / electromagnetic）**＋ COCO2017**。exp_001 の実測値の再現確認を兼ねるため、3ドメインに限定せず全6ドメインで取る。

## 3. テキスト入力・共通設定

- 026-1〜4 は exp_024/025 と同一の新 regime: **OD-ODVG ＋ `RandomSamplingNegPos`**（同一ドメイン負例）、num_sample_negative=85 / full_sampling_prob=0.5 / max_tokens=256、`num_classes=256` 統一、**seed=0**。
- バッチ: **現在ドメイン 4/GPU**（`batch_size=4`）、4GPU 分散。リプレイ無しなので exp_024/025 と同じ。
- 026-5 は学習を伴わないため、評価 config（`eval_{domain}.py` / `eval_base_coco.py`）のみを使う。

## 4. 学習スケジュール

- **026-1 / 026-2（個別チューニング）**: epoch=20、milestones=[15]（gamma=0.1）、lr=1e-4、AdamW（wd=1e-4）。逐次学習の各ドメインと同一設定にし、「逐次でなければどこまで行くか」を同条件で比べられるようにする。初期値は**全ドメインとも θ0**（前ドメインを引き継がない）。適応 mAP は last。
- **026-3（個別 ZiRa）**: ZiRa 論文準拠（exp_023 と同一）——IterBasedTrainLoop **2000 iter**、AdamW **lr 1e-3 / wd 1e-4**、iter800 で lr×0.1、LLRB のみ lr×0.2、λ=0.1。初期値は θ0。
- **026-4（オラクル）**: 条件A（全モジュール）、lr=1e-4、**epoch=20**（2026-07-24 決定）。3ドメインの train を `ConcatDataset` で結合して1モデルを同時学習する。各画像は**自ドメインのクラス名のみをプロンプト**（`return_classes=True`）とし、全クラスを1プロンプトに連結しない（テキスト長制限を発生させない。`research_plan.md` §6.1）。
  - エポック数は逐次学習の各ドメインと同じ 20 に揃える。結合により1エポックあたりのデータ量は約3倍（合計 46,264 枚）になるため、総更新回数は逐次学習の1ドメイン分より多くなるが、エポック数の定義を揃えることを優先する。
  - **規模不均衡は均衡化しない**（2026-07-24 決定）。`RepeatDataset` 等は使わず、素の `ConcatDataset` で自然な分布のまま学習する。実測の train 画像数は **underwater 12,633（27%）/ electromagnetic 25,398（55%）/ videogames 8,233（18%）**、合計 46,264 枚で、最大:最小 ≈ 3.1:1 と偏りは中程度。均衡化は倍率というハイパラを増やし「全ドメインを同時に見た上限」という素直な解釈から離れるため採らない。
  - 事後の検出可能性: 露出比の小さい videogames のオラクル mAP が **026-1（個別チューニング 条件A）の videogames を下回った場合**、露出不足が効いた可能性のサインとなる。その場合は均衡化を入れて取り直すかを、結果を見てから判断する。

## 5. 評価・判定基準

- **026-1〜3（個別）**: 学習後に (a) **自ドメインの適応 mAP**、(b) **ZCOCO**。過去ドメインは存在しないため測らない。
- **026-4（オラクル）**: 学習後に (a) **3ドメインそれぞれの mAP**、(b) **ZCOCO**。
- **026-5（ゼロショット）**: θ0 で **6ドメインそれぞれの mAP** ＋ **COCO mAP**。
  - **判定**: exp_001 の実測値と一致するかを見る（COCO **0.504** / underwater **0.051** / aerial **0.034** / electromagnetic **0.024** / videogames **0.016** / documents **0.006** / microscopic **0.002**）。学習を伴わず評価は決定的なので、**ほぼ一致するはず**。乖離があれば θ0・データ・評価設定のいずれかに差があることを示すため、原因を切り分ける。
- 忘却は個々のドメインごとに計算し、全ドメイン平均は取らない。
- 本実験は基準線の整備が目的のため、合否判定ではなく実測値の収集を行う。

## 6. 実装（承認後に着手、実行前に検証）

- **新規 config**（既存無変更）:
  - **個別チューニング用の config は新規作成しない**（2026-07-24 実装時の判断）。逐次実験の config をドライバからそのまま流用する——条件A は exp_024 の `fullft_replayfree_{domain}.py`、条件B は exp_025 の `condB_replayfree_{domain}.py`、ZiRa は exp_023 の `zira_replayfree_{domain}.py`。逐次との違いは**ドライバが `load_from` に前ドメインを渡さず常に θ0 から始める**ことだけであり、config を分けないことで「個別 vs 逐次」の差が**初期値だけ**に閉じ、比較が厳密になる（config を複製すると設定のドリフトが起き得る）。
    - ZiRa のみ exp_023 の config が `backbone.init_cfg` を URL のまま持つため、ドライバが `--cfg-options model.backbone.init_cfg=None` を渡して exp_026 の決定に合わせる（重みへの影響は無し）。
    - ZiRa の評価は**融合前の生 last ckpt**を使う（exp_023 の逐次ドライバと同一。Rep+ 融合は次ドメイン用の処理で、個別学習では不要）。
  - `experiments/exp_026/configs/oracle_condA_joint.py`（1本・新規）——3ドメインの `ConcatDataset`（均衡化なし）。exp_024 のベースを継承しスケジュールを揃える。
  - 評価は exp_023 の `eval_{domain}.py` / `eval_base_coco.py` を流用。ゼロショット用の **aerial / microscopic / documents** は、exp_023 と同じ2行パターン（`configs/mm_grounding_dino/grounding_dino_swin-t_finetune_8xb4_20e_{domain}.py` を継承し `model.bbox_head.num_classes=256` を上書き）で追加する。継承元の finetune config は**6ドメイン全てに既存**で、評価プロトコル（解像度 800,1333）も `eval_base_rf100.py` に固定済みのため、作業は軽微。
- **backbone の `init_cfg` を無効化する**（`model.backbone.init_cfg=None`。2026-07-24 決定）。学習を伴う 026-1〜4 に適用。理由・検証は [[../exp_024/design]] §7 と同じ（`load_from` が backbone 187 パラメータを全て上書きするため最終重みに影響せず、全 908 テンソルの一致を実測で確認済み）。026-5（ゼロショット）は評価のみで `init_weights()` を通らないため元から無関係。
- **ドライバ**: `experiments/exp_026/run_indiv.sh`（個別9本）／`run_oracle.sh`／`run_zeroshot.sh`（評価7本）。
- **クラスタ実行**: `experiments/exp_026/{sbatch.sh, train_val.sh}`。個別9本は短〜中時間なので、同時実行4ジョブの枠で並列に流す（exp_024/025 の長時間ジョブと枠を分け合う点に注意）。
- **実装検証（実行前）**: (a) 個別学習で `load_from` が常に θ0 になっていること、(b) 条件B の凍結が効いていること、(c) オラクルの `ConcatDataset` で各画像が自ドメインのクラス名のみをプロンプトにしていること（`return_classes=True` の経路確認）、(d) ゼロショット評価で θ0 以外の重みが混入していないこと。

## 7. この実験で言えないこと（限界）

- 個別チューニング・オラクルは逐次学習ではないため、忘却そのものは測れない（あくまで基準線）。
- 026-4 のオラクルは3ドメインのみで、6ドメイン全体の上限ではない。
- ゼロショットの再確認は θ0 の再現性確認であり、新しい知見を生むものではない。
- 提案手法（蒸留）の有効性は扱わない（実験2）。
