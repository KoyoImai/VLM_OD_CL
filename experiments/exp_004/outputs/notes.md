# exp_004 メモ：underwater fine-tune（backbone・言語 凍結）

## 結論（重要・反直感的）
backbone・言語エンコーダを凍結すると、**適応も忘却も全体FT(exp_003)より悪化**した。
「凍結すれば忘却を抑えられる」という当初の予想は、本アーキテクチャ・本設定では**成立しなかった**。

| | 適応(underwater) | 忘却(COCO) |
|---|---:|---:|
| zero-shot | 0.051 | 0.504 |
| 全体FT (exp_003) | **0.340** | **0.438**（−13.1%） |
| 凍結FT (exp_004) | 0.316 | 0.414（**−17.9%**） |

凍結FT は underwater が低く（適応不足）、かつ COCO がより大きく低下（忘却増）。**両負け**。

## なぜ凍結で忘却が増えたか（仮説）
- MM-Grounding DINO の **検出 head/encoder/decoder/neck は COCO と underwater で共有**される
  （テキスト対照ベースで num_classes 非依存）。
- backbone・言語を凍結すると、**underwater への適応圧力がすべて共有検出部に集中**し、
  COCO が依存するまさにその経路を強く歪める → 忘却が増える。
- 一方 全体FT は backbone・言語が 0.1×(実lr1e-5) で少し動くことで適応を分散吸収し、
  共有検出部の歪みが相対的に小さく済む → 同程度の学習でも COCO 劣化が小さく、適応も高い。
- つまり本設定の忘却源は backbone ではなく **共有検出デコーダ/ヘッド**にある可能性が高い。

## 含意
- 「本体凍結」は単純な忘却抑制策にならない。**どこを凍結するか**が本質。
- ZiRa が有効なのは「凍結＋別経路アダプタ＋出力ノルム正則化(ZiL)」で、
  **共有検出部を直接歪めずに**適応を別ブランチに逃がすため、と整合的に理解できる
  （[[../../papers/ZiRaGroundingDINO_summary]]）。本実験はその裏返しの証拠。

## 妥当性
- exp_003 と差分は backbone・言語の lr_mult のみ（0.1→0.0）。他は完全同一。比較は公平。
- 評価は (800,1333) プロトコル統一。学習中 val と test 一致（0.316）。
- 凍結FT の best は ep20（まだ微増）＝収束やや遅め。20ep 固定の比較なので「同 epoch 条件下」の結論。

## 次の問い・改善案
1. **デコーダ/ヘッドの凍結 ablation（exp_005 候補）**: 逆に「backbone・言語は学習、検出デコーダの一部を
   凍結」したら忘却が減るか。忘却源が共有検出部という仮説を直接検証。
2. **アダプタ方式（ZiRa 型）**: 本体は触らず別ブランチで適応＋ZiL。本実験（両負け）に対する
   有効性を検証する本命。
3. **凍結FT の収束確認**: ep20 で頭打ち未達のため、凍結時のみ epoch 延長 or lr 調整で
   適応上限を測り直す（公平比較とは別に、凍結の真の適応上限を把握）。
4. **学習率感度**: 共有検出部に圧力が集中する凍結時は lr 低減で忘却が減るか（適応とのトレードオフ）。
