## 0. 位置付け

exp_028 が条件A（全モジュール学習）で蒸留対象を切り分けるのに対し、本実験は**同じ切り分けを条件B（特徴抽出+融合のみ学習）で行う**。実験4 で条件A と条件B の適応がほぼ同等であることが分かっており（差は9組中7組がばらつきの範囲内）、note04 の判定基準に従って両方を実験5 以降に持ち越している。

## 1. 構成（4条件）

| # | 蒸留対象 | 形式 | 学習範囲 | ジョブ |
|---|---|---|---|---|
| 029-A | 画像（neck 出力） | L2 | 条件B | **exp_029_a** |

## 2. exp_028 からの差分

| 項目 | exp_028 | exp_029 |
|---|---|---|
| 学習範囲 | 条件A（全モジュール） | **条件B（特徴抽出+融合）** |
| 継承する config | exp_027 の `fullft_replay_{domain}.py` | exp_027 の **`condB_replay_{domain}.py`** |
| 対照 | exp_027-1 | **exp_027-2** |
| λ 校正の参照学生 $\theta^{\mathrm{ref}}_t$ | exp_027-1 の各ドメイン last | **exp_027-2 の各ドメイン last** |
| 蒸留の定式化（§4） | — | **同一**（対象・縮約・距離・$\rho=0.1$ すべて exp_028 と同じ） |
| データ・リプレイ・スケジュール・評価 | — | **同一** |

条件B の学習範囲は exp_023 以来の定義をそのまま用いる。`lr_mult` による指定で、実効 lr が 0 になるモジュールが凍結対象である。

| | モジュール |
|---|---|
| 学習 | backbone (0.1)、language_model (0.1)、neck (1.0)、text_feat_map (1.0)、encoder (1.0)、level_embed (1.0) |
| 凍結 | decoder、bbox_head、memory_trans_fc、memory_trans_norm、query_embedding、dn_query_generator（すべて 0.0） |

**蒸留対象（neck 出力・`text_feat_map` 出力・encoder 出力）はいずれも学習対象のモジュールが生成する**ため、条件B でも蒸留の勾配経路は成立する。

## 3. 条件B に固有の注記（結果の解釈に効く）

**条件B では、encoder 出力より下流が教師と学生でビット単位で同一である。** 凍結は `lr_mult=0.0` で実装されており、`load_from` で $\theta_{t-1}$ を読んだ後、decoder・bbox_head・memory_trans_fc/norm・query_embedding・dn_query_generator は一切更新されない。教師 $\theta^T = \theta_{t-1}$ の同じモジュールと完全に一致する。

このため次が成り立つ。

- **蒸留D（融合後）を条件B にかけた場合**、$\mathcal{L}_{\mathrm{fus}} \to 0$ の極限で、バッファ内データに対する**検出結果そのものが教師と一致する**。encoder 出力 `memory` / `memory_text` が同じで、その先の処理が同一の重みだからである。すなわち 029-D は、実質的に**バッファ内データに限定した出力レベルの蒸留**に近い性質を持つ。
- **条件A（exp_028）では成り立たない。** 下流も学習で動くため、特徴が保存されても出力は保存されない。

蒸留A・B（neck 出力・`text_feat_map` 出力）については、encoder が学習対象であるため、条件B でも出力の保存は導かれない。**条件B で特別なのは蒸留D だけである。**

### 3.1 本実験内の比較が均質でなくなる（主要な影響）

蒸留A・B・D を分けた狙いは「**ネットワークのどこに蒸留をかけると効くか**」の切り分けである。しかし条件B では、encoder が**最後の学習可能な地点**にあたるため、この切り分けが均質でなくなる。

| 蒸留対象 | 学習範囲の中での位置 | 制約の及ぶ範囲 |
|---|---|---|
| A（neck 出力） | 途中 | その先（encoder）は動ける |
| B（`text_feat_map` 出力） | 途中 | その先（encoder）は動ける |
| **D（encoder 出力）** | **出口** | **下流すべてが決まる（＝検出結果が固定される）** |

したがって、仮に 029-D が最も良い結果を示しても、それを「融合後の特徴が忘却の要である」とは読めない。「学習範囲の出口を押さえたため、下流の出力ごと固定された」という説明が同時に成り立つためである。**この2つを exp_029 の内部だけで分離することはできない。**

条件A（exp_028）では decoder・bbox_head も学習対象なので D は出口ではなく、A・B・D はいずれも「途中の一点を押さえる」制約になる。**当初の狙いに沿った比較が成立するのは exp_028 のほうである。**

### 3.2 実験間の比較への影響

028-D と 029-D は「同じ場所に蒸留をかけた2条件」ではあるが、上記のとおり**制約の届く範囲が異なる**。両者の差を「条件A と条件B の差」として読む際には、この非対称性を考慮する必要がある。

### 3.3 手法の記述への影響

029-D が選ばれて実験6 の土台になった場合、その手法を「特徴蒸留」と記述するのは正確でない。条件B の下では、バッファ内データに限定した**出力蒸留**と機能的に等価だからである。新規性の主張に関わるため、結果を見る前にここに記録しておく。

## 4. 対照と λ 校正（実行前の依存関係）

- **対照**: exp_027-2（条件B + リプレイのみ、クラスタ）。同一環境で揃える必要があり、本環境の exp_023 手法6 で代用すると環境差（実測で最大 0.012）が蒸留の効果と交絡する。
- **λ 校正**（exp_028 §4.5 の参照ドリフト方式）には exp_027-2 の各ドメイン last ckpt が必要である。

**2026-07-27 時点の exp_027-2 の状態**: underwater・electromagnetic は学習と評価が完了、videogames は学習中（9/20 エポック）。videogames の校正と、t=3 の対照値の確定はその完了を待つ。underwater・electromagnetic の校正は先行して実施できる。

## 5. 実装

exp_028 と同一のコンポーネントを使う。新規に作るのは config とドライバのみ。

- **config**: `experiments/exp_029/configs/kd{A,B,D,E}_condB_l2_{domain}.py`。exp_027 の `condB_replay_{domain}.py` を継承し、`model.type` を `KDGroundingDINO` に変え、蒸留の設定（対象・形式・$\lambda$）を追加する。`paramwise_cfg` は継承元のまま変更しない。
- **detector / loss**: `mmdet/models/detectors/kd_grounding_dino.py`、`mmdet/models/losses/feature_distill_loss.py`（exp_028 で作成したものを再利用。無変更）。
- **ドライバ・クラスタ実行**: `run_sequential_kd.sh`（exp_028 と共用）と、`_a` / `_b` に分けた `train_val_{a,b}.sh` / `sbatch_{a,b}.sh`。ジョブ名は `exp029a_kdAB_condB_l2` / `exp029b_kdDE_condB_l2`、PORT は 29680 / 29690。`#SBATCH --exclude=node03` を入れる。

### 実装検証（実行前・本環境で実施）

exp_028 の検証項目に加えて、条件B 固有の2点を確認する。

1. **凍結が効いていること**: 上表の6モジュール（229 パラメータ）の実効 lr が 0 で、1 ステップ後に重みが不変であること。exp_025 で確立した手順をそのまま用いる。
2. **§3 の性質が実際に成り立つこと**: $\theta^S = \theta^T$ の状態（学習開始時点）で、バッファ内データに対する検出出力が教師と完全に一致すること。さらに数ステップ学習した後、encoder 出力の差と検出出力の差が対応して増えることを確認する。
3. exp_028 の検証項目1〜7 も同様に実施する（教師の凍結、バッファ限定、$\mathcal{L}_{\mathrm{KD}}=0$、勾配経路、数式一致、マスク、θ0 ロード下での実施）。

## 6. コスト・運用

- 1条件が3ドメイン逐次で約43時間。4条件で **約172 GPU時間**だが、`_a` / `_b` の2ジョブに分かれるため**各ジョブ約86時間**。並列に投入すれば実時間 約86時間。
- ディスク: 4条件 × 3ドメイン × 20 × 2.0GB = **約480GB**。実験5 全体（16条件）で約1.9TB になる点は exp_028 §8 に記載のとおり。
- クラスタ枠: 同時4ジョブ。exp_028 と同時には流せない。

## 7. この実験で言えないこと（限界）

exp_028 §9 と同じ限界に加えて、

- §3 の非対称性により、028-D と 029-D の差を「条件A と条件B の差」だけに帰属させることはできない。
- 条件B の凍結範囲は1通りのみ（note04 の定義）。どこまで凍結すべきかの探索は行わない。
