# exp_003 メモ：underwater 単一ドメイン fine-tune

## 結論
underwater 単一ドメインの fine-tune により、継続学習の2軸を初めて同時に観測した。

| 軸 | zero-shot | fine-tune後 | 解釈 |
|---|---:|---:|---|
| 適応（underwater） | 0.051 | **0.340** | ドメイン適応の余地は大きい（+0.289, 約6.7倍）= upper bound |
| 忘却（COCO/ZCOCO） | 0.504 | **0.438** | 1ドメイン学習でも汎用知識が低下（−0.066, −13.1%）= 破滅的忘却の発生 |

→ **適応は大きく進むが、その代償として汎用ドメイン（COCO）の性能が確かに失われる**ことを定量確認。
本研究の課題2（破滅的忘却）が、わずか1ドメインの fine-tune でも現れることを示した。

## 観察
- **適応**: underwater は zero-shot で「位置は拾えるがクラス対照が弱い」状態だった（exp_000/001）。
  fine-tune で mAP_50=0.518 まで上昇し、ドメイン固有クラス（サンゴ分類等）の対照が大きく改善したと推測。
  小物体 mAP_s も 0.009→0.169 と大幅改善。
- **忘却**: COCO は 0.504→0.438（−13.1%）。backbone・言語を 0.1× とはいえ更新したため、
  汎用表現が underwater 寄りにずれた。mAP_s が 0.375→0.293 と特に低下＝COCO の小物体検出が劣化。
- **学習推移**: ep6 で 0.30 到達後は緩やかに飽和、ep18 が best。20ep は十分だが、
  忘却を抑えるならより短いスケジュールでも適応の大半は得られる可能性（ep6 で 0.30）。

## 妥当性・トラブル
- 初回 per-GPU16（実効64・累積なし）は OOM（GPU3）→ NCCL ハング。
  per-GPU8 + 累積2（実効64維持, lr=1e-4）で再実行し完走。詳細は results/finetune_summary.md。
- 評価は (800,1333) プロトコル統一。underwater 適応値は学習中 val と test で一致（0.340）。

## 次の問い・改善案
1. **忘却 vs 適応のトレードオフ曲線**: lr / epoch / 凍結範囲を変えたとき、
   適応（underwater↑）と忘却（COCO↓）がどう動くか。例: backbone・言語を完全凍結すると忘却は減るか。
   → 「凍結範囲 ablation」を exp_004 候補に。
2. **エポック短縮の効果**: ep6（mAP0.30）と ep18（0.340）で COCO 忘却量を比較。
   短い学習で「適応の大半 × 忘却小」が得られるかを検証。
3. **逐次2ドメインへ拡張**: underwater→他ドメインと続けたとき、underwater 自体の忘却も発生するか
   （継続学習の本丸）。ドメイン順序の影響検証へ。
4. **忘却抑制手法の導入**: ZiRa 型（本体凍結＋アダプタ＋ZiL）を MM-GDINO に実装し、
   本実験の標準 fine-tune（COCO −13.1%）をどれだけ抑制できるか比較。
