## 0. 位置付け

exp_028 は $\lambda = 1.0$ 固定であり、design §4.5 に記録したとおり**対象間で実効強度が最大 473 倍
違う**（underwater・ドリフト後の実測: 蒸留B 6.97 / 蒸留A 0.278 / 蒸留D 0.0147）。そのため
exp_028 の A/B/D/E 比較は「どこに蒸留をかけるか」に加えて「どれだけ強くかかるか」の差を含む。

本実験は **蒸留損失が検出損失の一定割合になるよう、係数を毎イテレーション自動計算する**。
これにより

- **対象間**（A/B/D/E）の実効強度が揃う
- **学習の進行中**も強度が一定に保たれる（exp_028 では学習が進むほどドリフトが増え、蒸留が相対的に強くなる）

という2つの正規化が同時に得られる。exp_028 との差は**重みの決め方だけ**なので、両者の比較で
「強度の揃え方が結果に効くか」が読める。

## 1. 定式化

ミニバッチごとに次を計算する。

$$
\mathcal{L} = \mathcal{L}_{\det} + \lambda_t \, \mathcal{L}_{\mathrm{KD}},
\qquad
\lambda_t = \mathrm{sg}\!\left[\rho \cdot \frac{\mathcal{L}_{\det}}{\mathcal{L}_{\mathrm{KD}} + \varepsilon}\right]
$$

**記号について（重要）**: 本実験の $\rho$ は **目標割合**であり、exp_028〜031 の $\lambda$（蒸留損失に
掛ける**係数**）とは別の量である。同じ数値でも意味が違うので、たとえば「exp_028 の $\lambda=1.0$」と
「exp_032 の $\rho=0.1$」を 10 倍の差として読むことはできない。$\rho$ という記号は
[[../exp_028/design]] §4.5 の校正手順で既に同じ役割に使われており、それに合わせている。
本実験は §4.5 の校正を**毎イテレーション行う版**にあたる。

- $\mathcal{L}_{\det}$: MM-Grounding DINO の通常損失の合計（39項。`loss_kd` を除き、キーに `loss` を
  含む全項目の和。mmengine の `parse_losses` と同じ集計）
- $\mathcal{L}_{\mathrm{KD}}$: exp_028 §4.4 と同一（蒸留対象により img / txt / fus / 3項平均）
- $\mathrm{sg}[\cdot]$: **stop-gradient**。$\lambda_t$ は定数として扱い、$\mathcal{L}_{\det}$ や
  $\mathcal{L}_{\mathrm{KD}}$ を通じた勾配を流さない
- $\rho$: **目標割合**（設定値）。$\varepsilon = 10^{-12}$

この定義により、**毎イテレーション厳密に**

$$\lambda_t \, \mathcal{L}_{\mathrm{KD}} = \rho \, \mathcal{L}_{\det}$$

が成り立つ（$\varepsilon$ の効果を除く）。すなわち蒸留損失の値は常に検出損失の $\rho$ 倍になる。

### 1.1 $\rho$ の値

**$\rho = 0.1$**（検出損失の 10%）を既定とする。

**exp_028 の実測との対応（2026-07-31 追記）**: exp_028 は係数 $\lambda = 1.0$ 固定だったため、
実際の割合は対象ごとに大きく違っていた。$\rho = 0.1$ にすると各対象の強度は次のように変わる。

| 蒸留対象 | exp_028 の実際の割合 | exp_032（$\rho=0.1$） | 変化 |
|---|---:|---:|---|
| A（画像） | 5.4% | 10% | 1.9 倍 強く |
| B（テキスト） | **135%** | 10% | 13.5 倍 弱く |
| D（融合後） | 0.28% | 10% | **36 倍 強く** |
| E（3項平均） | 47% | 10% | 4.7 倍 弱く |

exp_028 の結果（2026-07-31 時点）では、最も強くかかっていた蒸留B（135%）でも差がばらつきの
範囲を出ず、唯一トレードオフらしい動きを見せたのは蒸留E（47%）だった。したがって
**$\rho = 0.1$ は蒸留D・A には新しい情報を与えるが、B・E については exp_028 より弱い条件を
試すことになる**。$\rho$ の値は再検討の余地がある（§7 の限界を参照）。

### 1.2 分散学習での扱い

$\mathcal{L}_{\det}$ と $\mathcal{L}_{\mathrm{KD}}$ は GPU ごとに異なる。**全 GPU で平均してから
$\lambda_t$ を計算する**（`all_reduce` で平均）。GPU ごとに別々の $\lambda_t$ を使うと、勾配平均後の比率が
$\lambda$ にならないため。

### 1.3 勾配について（重要な性質）

$\lambda_t$ は定数なので勾配は $\lambda_t \nabla \mathcal{L}_{\mathrm{KD}}$ である。**損失の値は固定されるが、
勾配の大きさは固定されない。**

このことから2つの帰結がある。

- **自己均衡**: 蒸留が効いて $\mathcal{L}_{\mathrm{KD}}$ が下がると $\lambda_t$ が上がり、押し戻す力が
  維持される。exp_028 の固定重みでは、ドリフトが小さいうちは蒸留がほとんど効かない。
- **学習初期の不安定リスク**: 学習開始時は $\theta^S = \theta^T$ なので $\mathcal{L}_{\mathrm{KD}}$ は
  確率的な床（dropout と drop path による揺らぎ）だけになる。実測（underwater、train モード）では
  蒸留D の床が 0.00093、そのときの $\mathcal{L}_{\det}$ が 17.97 なので

  $$\lambda_t = \rho \times \frac{17.97}{0.00093} = 0.1 \times \frac{17.97}{0.00093} \approx 1{,}900$$

  となる。損失の値は $0.1 \times 17.97 = 1.80$ に収まるが、**勾配は $\nabla\mathcal{L}_{\mathrm{KD}}$
  の 1,900 倍**になる。このとき $\mathcal{L}_{\mathrm{KD}}$ の中身はドリフトではなく dropout ノイズ
  なので、**ノイズの勾配を 1,900 倍して流すことになる**。

  対策として上限 `max_weight` を設ける（既定 **100**）。上限に達した回数はログに残し、学習初期に
  どれだけ効いたかを事後に確認できるようにする。上限が頻繁に効く場合、実質的に「初期は固定重み、
  ドリフトが増えてから比率追従」という挙動になる。

## 5. 実装

- **コード変更**: `mmdet/models/detectors/kd_grounding_dino.py` に重みの決め方を追加する。
  config の `model.kd.weight_mode` で切り替える。

  | `weight_mode` | 挙動 | 使う実験 |
  |---|---|---|
  | `'const'`（既定） | `loss_weight` をそのまま使う | exp_028〜031 |
  | `'ratio'` | $\lambda_t = \rho\,\mathcal{L}_{\det}/\mathcal{L}_{\mathrm{KD}}$ を毎イテレーション計算 | **exp_032** |

  既定を `'const'` にすることで、**exp_028〜031 の挙動は一切変わらない**。
- **config**: `experiments/exp_032/configs/kd{A,B,D,E}_condA_l2ratio_{domain}.py`。exp_028 の対応
  config を継承し、`model.kd.weight_mode='ratio'`・`target_ratio=0.1`・`max_weight=100` を足すだけ。
- **ログ**: 診断値として `kd_lambda`（実際に使われた $\lambda_t$）と `kd_ratio`（達成された
  $\lambda_t\mathcal{L}_{\mathrm{KD}}/\mathcal{L}_{\det}$）を出す。キー名に `loss` を含めないので合計には入らない。
- **ドライバ・クラスタ実行**: `run_sequential_kd.sh` を共用。`FORM` に `l2ratio` を渡す。
  `experiments/exp_032/{train_val_{a,b}.sh, sbatch_{a,b}.sh}`、ジョブ名
  `exp032{a,b}_kd{AB,DE}_condA_l2ratio`、PORT 29740 / 29750。`--exclude=node03`。

### 実装検証（2026-07-29 実施）

1. **割合が厳密に成り立つこと** — **合格**。4対象 × 3バッチで達成割合が **0.100000**。
   そのときの $\lambda_t$ は 蒸留A 1.78〜2.83 / 蒸留B 0.068〜0.080 / 蒸留D 34.4〜41.3 /
   蒸留E 0.199〜0.234 と対象ごとに 500 倍違う値を自動で取る。
2. **既定の後方互換** — **合格**。`weight_mode` を書かない exp_028 の config は
   `weight_mode='const'` / `kd_weight=1.0` で読まれ、損失値が変更前と一致。
3. **上限の挙動** — **蒸留D のみ上限に張り付く**。学習開始時（$\theta^S=\theta^T$）の実測:

   | 蒸留対象 | $\lambda_t$ | 達成割合 | 上限到達 |
   |---|---:|---:|---:|
   | A | 7.67〜13.60 | 0.1000 | 0/3 |
   | B | 0.52〜0.82 | 0.1000 | 0/3 |
   | **D** | **100.00**（上限） | **0.0025〜0.0555** | **3/3** |
   | E | 1.37〜2.29 | 0.1000 | 0/3 |

   蒸留D は開始時の $\mathcal{L}_{\mathrm{KD}}$ が確率的な床（0.00093）しかないため、割合を
   満たすには $\lambda_t \approx 1{,}900$ が必要になる。上限 100 で止めているので開始時は
   目標の 2.5〜5.5% しか効かない。ドリフトが増えれば解消される（$\lambda_t$ が 100 → 34〜41）。

**未実施**: 勾配が二重に流れないこと（$\lambda_t$ の stop-gradient）と、分散時に全 GPU で
同じ $\lambda_t$ が使われることは、コード上は `detach()` と `all_reduce` で担保しているが
実測はしていない。

## 7. この実験で言えないこと（限界）

- 目標割合 $\rho = 0.1$ は1点しか試さない。割合そのものへの感度は分からない。**exp_028 の実測を踏まえると、$\rho=0.1$ は蒸留B・E にとって exp_028 より弱い条件になる**（§1.1）。$\rho = 0.5$ とすれば exp_028 で唯一動いた蒸留E の強度（47%）を全対象に揃えられる。
- 損失の値を揃えても**勾配の大きさは揃わない**（§1.3）。「実効強度を揃えた」と言えるのは損失値の
  水準についてのみである。
- 学習初期は `max_weight` の上限が効く可能性が高く、その区間は事実上の固定重みになる。上限の値
  （100）に根拠はなく、実行後にログで妥当性を確認する必要がある。
- exp_028 との比較は「固定 1.0 対 比率 0.1」であり、**固定重みの値を変えた場合との比較ではない**。
  「比率追従だから良い／悪い」と「たまたま強度が適切だった」を分離するには、固定重みで同等の強度に
  した条件が要る。
