# exp_005 メモ：他ドメイン凍結 fine-tune による忘却の普遍性

## 結論（目的達成）
backbone・言語凍結 fine-tune を6ドメイン（underwater 含む）で行った結果、
**すべてのドメインで COCO（事前学習で獲得した汎用知識）の精度が低下**した。
忘却は underwater 固有ではなく、**ドメインに依らず普遍的に発生する**ことを確認した。

| ドメイン | 適応(自) zs→FT | COCO 0.504→ | 忘却率 |
|---|---|---|---|
| underwater | 0.051→0.316 | 0.414 | −17.9%（最小） |
| electromagnetic | 0.024→0.454 | 0.331 | −34.3% |
| microscopic | 0.002→0.499 | 0.327 | −35.1% |
| videogames | 0.016→0.719 | 0.324 | −35.7% |
| aerial | 0.034→0.468 | 0.318 | −36.9% |
| documents | 0.006→0.478 | 0.275 | −45.4%（最大） |

## 観察
1. **忘却は普遍的かつ大きい**: 最小でも −17.9%、最大 −45.4%。たった1ドメインの fine-tune で
   COCO が大幅劣化する。継続学習（課題2）の深刻さを定量的に裏付け。
2. **適応はどのドメインも良好**: zero-shot がほぼ0だった microscopic(0.002→0.499)・
   documents(0.006→0.478)・videogames(0.016→0.719) も大きく適応。
   → 検出器自体の適応能力は高い。問題は「適応の代償としての忘却」。
3. **忘却量はドメインで差がある**:
   - underwater が突出して忘却が小さい（−17.9%）。underwater のクラス（fish/shark/penguin/
     starfish 等）は COCO の自然画像・動物と概念/見えが近く、共有検出経路の歪みが小さいと推測。
   - documents（表・図・レイアウト要素）が最大の忘却（−45.4%）。COCO と最も乖離したドメインで、
     共有検出経路を最も強く書き換えるためと考えられる。
   - → **「ドメインと COCO の距離」が忘却量と相関する**仮説。距離が遠いほど忘却が大きい。
4. exp_004 の知見（凍結でも忘却は共有検出デコーダ/ヘッドで起きる）と整合。本実験は backbone・言語を
   凍結してもなお全ドメインで忘却が起きることを示し、忘却源が共有検出部にあることを補強。

## 妥当性
- 全6ドメインで同一設定（凍結・lr1e-4・実効64・20ep・seed=0）。比較は公平。
- 評価は (800,1333) プロトコル統一。各ドメインで学習中 val と test がほぼ一致。
- OOM なく全完走（videogames は max_text_len=512 で最大33GB だが上限内）。

## 次の問い・改善案
1. **忘却 vs ドメイン距離の定量化**: COCO と各ドメインの距離（CLIP 特徴・クラス語彙の重なり等）を測り、
   忘却率との相関を検証。「documents 最大・underwater 最小」の仮説を定量的に裏付ける。
2. **逐次継続学習への移行（本丸）**: 単一ドメインではなく、6ドメインを逐次学習したときの
   (a) 各ドメインの忘却、(b) COCO の累積忘却、(c) ドメイン順序の影響、を測る。
3. **忘却抑制手法の導入**: ZiRa 型（本体凍結＋別ブランチアダプタ＋ZiL）を実装し、
   本実験の標準凍結FT（COCO −17.9〜−45.4%）をどれだけ抑制できるか比較。これが対策の本命。
4. **適応と忘却のトレードオフ制御**: epoch 短縮・lr 低減で「適応をある程度保ちつつ忘却を抑える」
   動作点が取れるか（exp_003/004 の全体FT vs 凍結の知見と合わせて）。
