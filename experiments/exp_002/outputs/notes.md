# exp_002 メモ：リサイズ感度分析と今後の学習・評価方法の計画

## 結論（要約）
- RF100 ドメインでは **短辺 640 / 800 / 1024 の差は誤差範囲（±0.002〜0.003 mAP）**。
- **短辺 1333（S3）は精度が崩壊**（COCO 0.504→0.021）。過度なアップスケールは厳禁。
- **正方形固定（S4）は RF100 では無影響**（元が 640×640 正方形）。COCO のような非正方形でのみ歪みで悪化。
- → **今後は学習・評価とも短辺 640（`(640,1333) keep_ratio=True`）に統一**することを推奨。

## 根拠
1. **640 はネイティブ解像度でアップスケールが無い**。RF100 は全画像 640×640。
   短辺 800/1024 は単なる拡大で情報は増えず、精度は誤差範囲（むしろ計算コスト増）。
2. **S2(1024) は一部ドメインで僅かに最良だが一貫しない**（aerial↑ だが underwater/documents↓）。
   全ドメインを通じた明確な勝者ではなく、コスト増に見合わない。
3. **学習側の多スケール拡張は短辺 480〜800**（[[resize_aug_investigation]]）。評価を 640 にすると
   学習レンジの中央付近に収まり、学習・評価の整合が取りやすい。
4. **RF100-VL の GroundingDINO 公式プロトコルも (640,1333)**（[[../../papers/Roboflow100_summary]]）。
   外部比較可能性の点でも 640 が妥当。

## 今後の学習・評価方法の計画
- **評価**: 全ドメイン・COCO とも `FixScaleResize (640,1333) keep_ratio=True` に統一。
  - COCO は 800→640 で 0.504→0.499 と僅差。忘却測定(ZCOCO)の基準も 640 に統一して問題なし。
- **学習**: train_pipeline の多スケール上限を 640 中心に寄せる案を次実験で検討。
  - 案A（標準維持）: 既存の短辺 480〜800 多スケールのまま（評価のみ 640）。
  - 案B（640 中心に統一）: 多スケールを 480〜640 に絞り、評価 640 と帯域を揃える。
  - まず案A（評価のみ 640 統一）でベースライン fine-tune を取り、必要なら案B を比較。
- **解像度上限**: 短辺 1024 超は採用しない（1333 で崩壊を確認）。

## 注意点・学び
- S3 高解像度は精度崩壊に加え、aerial/videogames で終了時クラッシュ（ChildFailedError）。
  高解像度 × 分散は不安定。本研究の解像度帯（640〜800）では問題なし。
- 評価リサイズによる順位変動はドメイン間で非一様（aerial は高解像度を好み、underwater は低解像度を好む）。
  ドメイン特性（物体サイズ分布）に依存するため、将来ドメイン別最適化の余地はあるが、
  継続学習の交絡を避けるため**当面は全ドメイン共通 640** とする。

## 次の問い・改善案
1. **fine-tune ベースライン（exp_003 候補）**: 評価 640 統一のもと、underwater / microscopic を
   fine-tune し、zero-shot(exp_001) からの伸び＝適応余地（upper bound）を測る。
2. **学習解像度の A/B（任意）**: 上記 案A vs 案B を 1 ドメインで比較し、学習帯域の影響を確認。
3. **忘却プロトコルの確定**: 評価 640 統一の COCO=0.499 を ZCOCO 基準として固定し、
   逐次 fine-tune 後の ZCOCO 低下を測る継続学習評価を設計。
