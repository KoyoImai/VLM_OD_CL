# 調査メモ：学習・評価時のリサイズ／データ拡張の挙動

exp_002（リサイズ感度分析）の前提整理として、MM-Grounding DINO の学習・評価パイプラインで
画像リサイズがどう振る舞うかを調査した結果をまとめる。元画像は RF100 のネイティブ **640×640**。

## 1. 結論
- 学習時のリサイズはすべて **`keep_ratio=True`（アスペクト比保持）**。
  640×640 の正方形画像が縦横で異なる比率に**引き伸ばされることはない**。
- **(450×1300) のような極端な縦横比への変形は起きない**。
- 長方形になり得るのは「RandomCrop でシーンの一部を切り取った」場合のみで、内容は歪まない。
  到達しうる最大アスペクト比は **約 1.56:1**（極端比 2.9:1 には届かない）。

## 2. 学習パイプライン（train_pipeline）の構造
`grounding_dino_swin-t_finetune_8xb4_20e_<domain>.py`（及び COCO 版）の train_pipeline は
`RandomChoice` で以下 2 分岐をランダムに選ぶ（各 50%）。すべて keep_ratio=True。

### 分岐1：通常の多スケール
`RandomChoiceResize scales=[(480,1333),(512,1333),…,(800,1333)]`
- `(短辺候補, 1333)` の形。1333 は「長辺の上限」。
- **正方形画像では短辺＝指定値の正方形**になる（長辺上限1333は発動しない）。

### 分岐2：大resize → RandomCrop → 多スケール
```
RandomChoiceResize scales=[(400,4200),(500,4200),(600,4200)] keep_ratio=True
RandomCrop crop_type='absolute_range' crop_size=(384,600) allow_negative_crop=True
RandomChoiceResize scales=[(480,1333),…,(800,1333)] keep_ratio=True
```
- RandomCrop は H,W それぞれを **[384, 600] の範囲**で切り取る → 長方形になり得る。
- ただしクロップは「実画像の部分領域」であり歪みではない。後段 resize も keep_ratio。

## 3. 実測（640×640 入力で検証）
mmcv の `RandomChoiceResize` / mmdet の `RandomCrop` を直接実行して確認。

### 分岐1
| scale | 出力 img_shape |
|---|---|
| (480,1333) | 480×480 |
| (640,1333) | 640×640 |
| (800,1333) | 800×800 |

→ 正方形のまま。比率は不変。

### 分岐2（resize(600,4200)→crop(384〜600)→resize(800,1333)）
| crop後 (H×W, AR) | resize後 (H×W, AR) |
|---|---|
| 584×385 (1.52) | 1214×800 (1.52) |
| 428×561 (1.31) | 800×1049 (1.31) |
| 405×511 (1.26) | 800×1009 (1.26) |
| 536×556 (1.04) | 800×830 (1.04) |
| 412×525 (1.27) | 800×1019 (1.27) |

→ 長方形にはなるが、crop 前後で AR が一致＝歪んでいない。

## 4. なぜ (450×1300) は不可能か
- RandomCrop の各辺は最大 600・最小 384 → 到達可能な最大アスペクト比は **600/384 ≈ 1.56:1**。
- (450×1300) のアスペクト比は **約 2.9:1** で上限を大きく超過。
- keep_ratio リサイズは比率を変えないため、後段でもこの比率にならない。

## 5. 起こり得る変形まとめ
| ケース | 起こるか | 例 |
|---|---|---|
| 正方形→正方形（分岐1） | ○ | 480×480〜800×800 |
| 正方形→緩やかな長方形（分岐2のcrop） | ○ | 最大 ~1.56:1（例 1214×800） |
| 正方形→極端な長方形 (≈2.9:1, 450×1300) | × | 起きない |

## 6. 評価側（test_pipeline）の補足
- 評価のリサイズは `FixScaleResize`。exp_001 は `(800,1333) keep_ratio=True` → 640×640 を 800×800 に。
- exp_002 で比較する設定:
  - S1 `(640,1333)` keep_ratio=True … 正方形 640 はリサイズなし
  - S2 `(1024,1333)` keep_ratio=True … 1024×1024 へアップスケール
  - S3 `(1333,2000)` keep_ratio=True … 1333×1333 へ
  - S4 `(640,640)` **keep_ratio=False** … 比無視で正方形化（640×640画像なら無変形、COCO等の非正方形でのみ歪む）

## 7. exp_002 への含意
- 学習は keep_ratio 維持で短辺 480〜800 を変動させる多スケール拡張。
- したがって「学習・評価のリサイズ統一」を考える際は、**評価の短辺をどこに置くか**が論点
  （ネイティブ640か、学習レンジ中心の800か、より高解像度か）。exp_002 の結果で決定する。
