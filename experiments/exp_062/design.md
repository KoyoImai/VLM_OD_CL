# exp_062 設計書: バッチ内訳の感度分析（Ours=蒸留E ＋ ER=リプレイ、クラスタ）

作成 2026-09-11。**実行前のユーザー承認ゲート**（行動原理1・3）。
関連: [[../exp_061/design]]（同一軸のバッファサイズ感度・内訳 [4,1,1]）、
[[../exp_058/design]]（バッファ拡張方式）、[[../exp_043/design]]（[4,2,2] の前例）。

## 0. 位置付け

exp_061 は内訳 **[4,1,1]**（現在4 : 参照O365 1 : 過去1）でバッファサイズを振った。
本実験は内訳を **[4,2,2]**（現在4 : 参照2 : 過去2、batch_size=8）に変え、
同じバッファサイズ軸（base〜b5）で Ours と ER を測る。exp_061 の [4,1,1] と対にすることで
「リプレイ成分（参照・過去）の比率を上げるとサイズ感度がどう変わるか」を見る。

## 1. 条件

- **内訳**: source_ratio=[4,2,2]、batch_size=8（CurrentEpochMultiSourceSampler）。
  内訳以外（λ=10・L2・教師 θ_{t-1}・スケジュール・seed 0・num_classes 256）は
  exp_061 と完全一致させ、**内訳だけを唯一の変更点**にする。
- **バッファサイズ**: exp_061（=exp_058/buffer）と同一ファイルで 5 点をクロス。

  | 条件 | 参照（O365） | 過去（/ドメイン） | 倍率 |
  |---|---|---|---|
  | base | 1,000 | 500 | 1× |
  | b2 | 2,000 | 1,000 | 2× |
  | b3 | 3,000 | 1,500 | 3× |
  | b4 | 4,000 | 2,000 | 4× |
  | b5 | 5,000 | 2,500 | 5× |

- **手法**: Ours（kdE）と ER（replay）。
- **base も新規学習**: [4,2,2] は exp_061（[4,1,1]）と内訳が異なるため、base（1×）を含む
  全 5 サイズが新規（exp_043 の [4,2,2] はバッファ構成が別のため再利用しない）。
- **ドメイン**: 6 通し。評価は各 t の学習済み 1..t ＋ ZCOCO。ckpt は epoch_20 のみ。

## 2. バッファ（exp_058 を再利用）

exp_058/buffer/ の入れ子拡張バッファ（seed 0・包含鎖・manifest 付き）をそのまま参照する。
Ours・ER・exp_061 と完全に同一ファイルのため、内訳以外の交絡が入らない。

## 3. 実装（承認後）

| 成果物 | 内容 |
|---|---|
| `gen_configs.py` | Ours=exp_035/040 kdE・ER=exp_027/040 replay を解決し、(a) sampler の |
|  | source_ratio=[4,2,2]・batch_size=8 に上書き、(b) バッファ ann_file を exp_058/buffer の |
|  | 各サイズに差し替え。2 手法 × 5 サイズ × 6 ドメイン = 60 本 |
| `run_sequential.sh` | `METHOD=ours|er COND=base|b2..b5` で 6 ドメイン逐次学習＋評価。既存はスキップ |
| `sbatch_*.sh` | 手法×条件でジョブ分割（O365 bind 必要） |
| `check_exp062_setup.py` | exp_061 との diff＝source_ratio と batch_size のみ・1 step 有限を検証 |

- 学習ジョブ数: 2 手法 × 5 サイズ × 6 ドメイン = 60。評価は各条件 27。
- VRAM: batch_size 6→8 で増えるため、投入前に 1 step 実測（exp_043 [4,2,2]×8 は A6000 Ada 48GB で実績あり）。

## 4. 記録・判定

`results/summary.md` に Ours・ER それぞれ base〜b5 の推移を事実のみ記録。
比較の主眼は exp_061（[4,1,1]）との差分＝「リプレイ比率を上げるとサイズ感度・適応/保持の
バランスがどう動くか」。判定基準はユーザーがノートで確定する。
